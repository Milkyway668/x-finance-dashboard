# X 金融信息看板

**在线访问**：https://milkyway668.github.io/x-finance-dashboard/

把 8 个 X（Twitter）投研账号的推文，自动翻译成中文、按主题归类、生成中文短评，做成一个每天早上一眼看完的静态看板。

> 演示数据抓取时间：2026-11-22。当前收录 8 个账号、56 条推文。

---

## 一、它解决什么问题

买方研究员每天要刷的账号很多，但：

- 推文是英文的，读起来慢
- 信息是碎片化的，看不出彼此关系
- 同一个话题分散在不同账号、不同日期

这个看板做三件事：**翻译 → 归拢 → 给出可溯源的摘要**。

---

## 二、页面怎么用

| 操作 | 效果 |
|---|---|
| 左侧点账号头像 | 只看该账号的内容；再点一次回到全部 |
| 顶部点「宏观 / 行业 / 公司」 | 只看该主题；再点一次取消 |
| 右上角选择时间范围 | 今天 / 最近 3 天 / 最近 7 天 / 全部，短评与推文同步变化 |
| 点短评里的账号名 | 跳到下方对应的推文并高亮 |
| 点「英文原文」 | 展开该条推文的英文全文 |
| 点「导出日报」 | 下载一份可发送的独立 HTML |

**筛选逻辑**：左侧是纵轴（谁说的），顶部是横轴（说什么），两者可叠加；时间范围作用于整个页面。

## 三、数据处理链路

```
① 抓取       Playwright 打开账号主页 → 取推文 ID → 逐条打开详情页取全文
                ↓（时间线正文必定被截断，所以只从时间线拿 ID）
② 完整性校验  末尾省略号 / 长度恰为 280 / 订阅墙 / 纯图片 → 打标记，不静默接受
③ 翻译       DeepSeek 逐句翻译（禁止概括），长文单独复检
④ 归类       DeepSeek 按规则给出主题，人工可覆盖
⑤ 写短评     DeepSeek 生成「今日短评」「专题短评」，每个结论必须挂推文 ID
⑥ 真实性闸门  脚本逐条核对：摘要里的每个数字必须能在所引推文原文中找到
                ↓ 不通过就中止，不写页面
⑦ 输出       生成 data.js，页面直接读取
```

一键运行：

```bash
python pipeline/update_all.py            # 完整流程（含抓取）
python pipeline/update_all.py --no-fetch # 跳过抓取，重跑翻译与短评
```

## 四、为什么可信

这是整个项目最核心的设计，不是"调了个大模型让它写总结"。

1. **每条结论都可溯源**
   短评每段末尾列出「来源：@账号」，点击可跳到对应推文；导出的日报里则是带推文 ID 的真实链接。

2. **数字必须回查原文**
   `pipeline/verify_digest.py`、`verify_summaries.py`、`verify_range.py` 会把摘要里的**每一个数字 token** 拿到所引推文的原文里比对，找不到就报错中止。

   实测中它抓到过真实错误：写"高通单车收入从 21 美元升到 76 美元"时只引用了根推，而这组数字来自串文第 3 条——人工审稿很容易漏，脚本一秒识别。

3. **抓取完整性有标记**
   抓不全的内容（X 折叠、订阅者专属、纯图片）会被打上 `truncated` / `subscriber_only` / `media_only` 标记，而不是假装完整。

4. **不做投资建议**
   页面与文档均声明：只做信息整理，不判断方向。短评脚本内置检查，出现"建议买入/目标价"等表述会报警。

## 五、目录结构

```
index.html              页面（单文件，样式与脚本内联）
data.js                 数据：推文、短评、专题摘要
config/accounts.json    监控账号列表（增删账号只改这里）
config/display_names.json  账号显示名映射
assets/avatars/         账号头像
pipeline/               数据管线
  fetch.py              抓取（含完整性校验）
  translate_new.py      新推文翻译 + 主题初判
  merge_new.py          合并进 data.js
  retranslate.py        修补翻译不完整的条目
  gen_summaries.py      分类/账号的专题短评
  gen_range_digest.py   各时间范围的短评
  verify_*.py           真实性校验（闸门）
  update_all.py         一键串联
worker/                 可选：Cloudflare Worker，用于"点即生成"
data/                   抓取原始数据、中间产物
```

## 六、可选：实时生成短评（Worker）

默认页面使用**预生成**的短评，离线可用、不需要 key。

如果希望"选中任意组合就现场生成"，需要部署 `worker/worker.js` 到 Cloudflare Workers（免费额度足够），把 API key 存放在服务端：

```bash
cd worker
npm i -g wrangler
wrangler login
wrangler secret put DEEPSEEK_API_KEY     # 粘贴你的 key
wrangler secret put ALLOWED_ORIGIN       # 例如 https://你的用户名.github.io
wrangler deploy
```

然后把 `index.html` 里的 `SUMMARIZE_URL` 改成部署得到的地址。

**本项目的 Worker 已部署**：`https://x-digest-api.2724314528.workers.dev`

页面行为：
- 选中分类或账号时，先显示预生成内容，同时在后台请求 Worker 现场生成，返回后替换
- 请求失败（网络不通、额度用尽）时自动回退到预生成内容，并提示原因，不会白屏
- Worker 只调用 DeepSeek，不接触 X，不涉及账号风险

**为什么不能直接在网页里调 DeepSeek**：key 写在前端等于公开，任何人 F12 就能拿到。

**国内访问提示**：`*.workers.dev` 的 DNS 在国内会被污染（实测解析到无关 IP），需要在代理规则里让该域名走代理；否则页面会回退到预生成内容。这也是为什么页面必须保留"预生成"这一层。

## 七、已知限制

- **抓取频率受控**：每个账号每次只取最近几条，避免触发风控；不是实时监控
- **订阅者专属推文**：只能拿到公开预览，已明确标注
- **登录态**：抓取依赖本地浏览器登录态（`.browser/profile`），已加入 `.gitignore`，不会上传
- **GitHub Actions 自动抓取的局限**：机房 IP 与本地同时登录容易触发 X 风控，更稳妥的做法是本地/自有机器抓取，Actions 只做生成与发布
- **翻译由模型生成**：已通过逐句要求与复检降低错误率，但仍建议对照原文
